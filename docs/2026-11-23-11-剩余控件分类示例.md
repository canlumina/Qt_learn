# 剩余控件：分类参考示例与学习路线

日期：2026-11-23

## 覆盖范围

按《Qt 基本控件速查》原有未勾选条目，补齐 52 个不同类的参考 demo。同一行中的多个类分别实现，QFrame 在一页同时演示边框容器与分隔线。

| 分类 | 数量 | 主要内容 |
| --- | --- | --- |
| 按钮 | 1 | QToolButton 的默认动作和下拉菜单 |
| 输入 | 10 | 浮点输入、纯文本、滑块、三种日期时间输入、旋钮、滚动条、字体和快捷键录入 |
| 显示 | 7 | 标签、进度、帮助文档、数码管、月历、图形画布和边框/分隔线 |
| 布局 | 6 | 纵向、横向、网格、表单、堆叠布局与弹簧 |
| 容器 | 9 | QWidget、分组、分页、滚动、分割、抽屉、停靠和多文档 |
| 数据 | 6 | QListWidget/QTableWidget/QTreeWidget 与三种 Model/View |
| 窗口 | 6 | QMainWindow、菜单栏、菜单、动作、工具栏和状态栏 |
| 对话框 | 7 | 消息、文件选择、自定义、单值输入、颜色、字体和进度对话框 |

完整学习入口：[学习路线与控件对照表](examples/README.md)。

## 工程组织

每个参考示例独立占用一对 `.h/.cpp`，按类型放在 `examples/` 的子目录中。构造函数和回调均提供中文注释，说明输入、用途、返回值或无返回值以及调用限制。页面基类统一为 QWidget，使用布局管理器，QObject 子对象由父对象释放。

根 CMake 新增 `add_subdirectory(examples)`，生成独立目标 `widget_examples`。浏览器可以按控件名或分类筛选，并按需创建页面。已有 `learn` 目标及 `demos/` 示例保留，用户正在编写的 PlainTextEdit 文件和对应 CMake 改动也保留。

教程按八个分类拆分，每个控件均包含用途、典型场景、常用 API、练习步骤、注意事项及完整头文件和实现。各分类源码目录提供 README，列出示例功能和源码入口。文档中的代码由 `examples/tools/render_docs.py` 读取实际文件生成，避免两份代码逐渐不一致。

《Qt 基本控件速查》同步补上对应的 ✅，并注明标记代表已有示例可参考，不等于用户已经完成学习。

## 运行

```bash
cmake --preset qt6-desktop
cmake --build build/qt6 --target widget_examples --parallel 4
./build/qt6/examples/widget_examples
```

切换到 Qt 5 时使用已有 `qt5-desktop` 预设及 `build/qt5` 目录。安装位置不同的环境需调整 `CMAKE_PREFIX_PATH`。

## 验证结果

- Qt 6.11.1 与 Qt 5.15.2：配置和 `widget_examples` 目标编译、链接通过。
- 通过临时 C++ 检查程序，在两套 Qt 的 offscreen 平台下逐个创建、切换全部 52 页，并检查筛选及恢复。
- 检查滑块/数值框双向同步、日志上限和只读切换、表格代理筛选、列表追加/删除、堆叠页切换、MDI 创建/关闭释放、进度完成/取消、自定义对话框确认回填，均通过。
- 调整到较小窗口并重新遍历页面，检查布局调整路径。offscreen 提示 `This plugin does not support propagateSizeHints()`，未导致检查失败；这不代表真实窗口系统的显示表现。
- `cppcheck --library=qt --enable=warning,performance,portability --std=c++11 --suppress=missingIncludeSystem --error-exitcode=1 -DQ_OBJECT= -Dslots= examples` 返回成功，无诊断警告。
- `python3 examples/tools/render_docs.py --check` 验证教程代码与源码一致。另核对目录清单覆盖 52 个不同类、104 个 demo 源文件和相应进度标记。
- 差异和新增内容敏感字段检查通过。

## 尚未验证的范围

没有在真实桌面上逐项手动操作所有对话框、快捷键和拖动行为；文件选择、颜色/字体选择等原生交互只做编译及页面创建检查。i.MX6ULL 交叉编译、开发板字体、触屏、小屏对话框、浮动窗口、剪贴板和窗口管理行为尚未验证。

模拟任务由 QTimer 驱动，不代表线程、文件 I/O 或硬件访问的完整实现。文件对话框只选择路径，不会保存或覆盖文件；输入框内容退出后不持久化。真实耗时任务应在线程中处理，并通过信号更新 GUI。
