# QSpinBox：用数值框调节窗口不透明度

日期：2026-11-17

## 本次做了什么

新增 `SpinBox` 示例页面，注册到主窗口左侧目录的 `QSpinBox` 项。页面左上角放一个 QSpinBox：范围 0～100，步长 10，初始值 100，数值后面带后缀文字。

数值变化时，槽函数把它换算成 0.0～1.0 的小数，设置为主窗口的不透明度。

代码逻辑是通的，但在开发机桌面（Hyprland / Wayland）和 i.MX6ULL 开发板上都**看不到窗口变透明**，原因是平台不支持，详见“遇到的问题”。

## 知识点

### 范围、步长、当前值、后缀

```cpp
spinBox->setSingleStep(10);   // 点一次箭头变化多少
spinBox->setRange(0, 100);    // 最小值和最大值
spinBox->setValue(100);       // 当前值
spinBox->setSuffix("...");    // 显示在数值后面的文字
```

- QSpinBox 默认范围是 0～99，步长 1。所以必须**先 `setRange()` 再 `setValue(100)`**，顺序反了 100 会被截成 99。
- 后缀只是显示用的文字，`value()` 取到的仍然是整数。对应还有 `setPrefix()` 设置前缀。

### valueChanged 信号在 Qt 5 里有重载

```cpp
connect(spinBox, QOverload<int>::of(&QSpinBox::valueChanged),
        this, &SpinBox::onValueChanged);
```

和 QComboBox 的 `currentIndexChanged` 是同一种情况：Qt 5（包括开发板上的 5.11.3）里 `valueChanged` 有 `int` 和 `QString` 两个版本，直接写 `&QSpinBox::valueChanged` 编译不过，要用 `QOverload<int>::of()` 指明用哪一个。Qt 6 里 `QString` 版本改名成了 `textChanged`，只剩一个，但工程要兼容 Qt 5，所以保留 `QOverload` 写法。

本例的 `setValue(100)` 写在 `connect()` 之前，所以程序启动时不会触发槽函数。

### 整数换算成小数

```cpp
double dobleValue = (double)value / 100.0;
```

两个整数相除，结果还是整数，`50 / 100` 得到的是 0。要得到 0.5，至少要有一个操作数是小数类型。

### setWindowOpacity() 和 window()

```cpp
this->window()->setWindowOpacity(dobleValue);
```

- `setWindowOpacity()` 的取值是 0.0（完全透明）到 1.0（完全不透明）。
- 它**只对顶层窗口有效**。对嵌在别的窗口里的子控件调用，Qt 直接忽略，不报错也不警告。
- `window()` 返回控件所在的顶层窗口，在这里就是主窗口。
- 窗口是否真的变透明，还取决于运行平台，见下一节。

## 遇到的问题

### 调节数值，窗口不透明度没有反应

现象：点数值框的箭头，数值在变，窗口没有任何变化，也没有报错。

原因有两个，叠在一起。

**原因一：对子控件调用无效。** 最初写的是 `this->setWindowOpacity(dobleValue)`。这里的 `this` 是示例页面，嵌在主窗口右侧，不是顶层窗口。Qt 源码里这个函数开头就是：

```cpp
if (!isWindow())
    return;
```

同样的写法放在 MainWindow 里是有效的，因为那里的 `this` 就是窗口本身。

解决：改成 `this->window()->setWindowOpacity(dobleValue)`。

**原因二：运行平台不支持窗口不透明度。** 这个功能要由平台插件实现。没有实现的平台会在终端打印：

```
This plugin does not support setting window opacity
```

| 运行环境 | 结果 | 依据 |
| --- | --- | --- |
| 开发机桌面（Hyprland），默认走 wayland 插件，Qt 5.15.2 和 6.11.1 | 不支持，打印上面的警告 | 实测 |
| 开发机桌面，加 `QT_QPA_PLATFORM=xcb` 运行 | Qt 不报警告，但推测窗口仍不会变透明 | Hyprland 的程序里没有 `_NET_WM_WINDOW_OPACITY` 这个属性名；没有实际看效果 |
| i.MX6ULL 开发板（linuxfb，Qt 5.11.3） | 不支持 | 查源码，linuxfb 没有实现；没有上板运行 |

Qt 5.11.3 源码里实现了这个功能的平台插件有 xcb（X11）、windows、cocoa（macOS）、eglfs、directfb 等。

解决：这一条改代码解决不了。当前示例在开发机和开发板上都没有可见效果。

排查方法：

- 功能没反应时，先看终端有没有 `This plugin does not support ...` 这类警告。
- 想知道程序实际用的是哪个平台插件，可以打印 `QGuiApplication::platformName()`。

## 验证与限制

- 用临时测试程序以无界面方式模拟点 5 次向下箭头：修改前（Qt 6.11.1）主窗口不透明度保持 1；修改后 Qt 5.15.2 和 Qt 6.11.1 都变为约 0.5。
- 沿用此前要求，本次不执行工程编译，也没有在真实桌面上运行查看效果。
- 在开发机和开发板上看不到窗口变透明。想要可见效果，可以改用 `QGraphicsOpacityEffect` 让页面内容变淡，它由 Qt 自己绘制，不依赖窗口系统；本次没有改。
- `SpinBox` 类继承的是 `QSpinBox` 而不是 `QWidget`，页面本身就是一个铺满的大数值框（页面中间的 “0” 和最右侧的箭头）。它没有连接任何槽，调它不会有反应。后续应改成继承 `QWidget`，和 QLineEdit 示例是同一个问题。
- 后缀写成了 `"%s不透明度"`，界面上会原样显示 `%s`，应为 `"%不透明度"`。
- 数值框宽度 100 放不下后缀，文字被截断。
- 范围下限是 0。在支持窗口不透明度的平台上，调到 0 窗口会完全看不见。
- 页面背景色用的是不带选择器的样式表，会一起传给里面的数值框。
- 新增函数尚未提供中文函数注释。
